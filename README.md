# Event-Driven Cache Simulation Framework

A sophisticated, parameterizable, and maximally object-oriented C++ framework for simulating hierarchical multi-core cache systems with directory-based MSI coherence.

## Project Overview

This simulator provides a detailed environment to study memory hierarchy performance, cache coherence protocols, and replacement policies. It uses a **discrete-event simulation engine** to model time-accurate interactions between cores, multiple cache levels (L1, L2, L3), a centralized directory, and main memory.

### Key Features
- **Hierarchical Cache**: Private L1s, grouped L2s (shared among $n$ cores), and a common L3.
- **MSI Coherence**: Full directory-based MSI protocol with transient states (`IS_D`, `IM_AD`, `MI_A`, etc.) and eviction handling.
- **Polymorphic Policies**:
  - **Replacement**: LRU, LFU, FIFO, PLRU, MRU.
  - **Write Policy**: Write-Back and Write-Through.
- **Language-Level Instrumentation**: A `MemWrapper<T>` template that intercepts memory accesses in regular C++ code using proxy objects.
- **Event-Driven**: Custom scheduler for precise timing and message passing with variable latencies.

## Code Navigation Guide

### 1. The Entry Point: `detectMemAccess`

Everything begins with a memory access. Whether generated by the `MemWrapper` in a C++ program or parsed from a trace file, the simulation is triggered by:
`void System::detectMemAccess(int core_id, AccessType type, uint64_t addr)`

**Sequence of Actions:**
1.  **Core Request**: `detectMemAccess` calls `coreRead` or `coreWrite` on the target core's **L1 Cache**.
2.  **State Logic (The State Pattern)**: The `Cache` looks up the `CacheLine`. It then delegates the request to the line's current **`MSIState`** (e.g., `InvalidState`, `SharedState`).
3.  **Network Messages**: If the request is a miss or requires a state change (e.g., S -> M), the state object sends a **`Message`** (e.g., `GETS`, `GETM`) via the **`Network`**.
4.  **Event Scheduling**: The `Network` calculates a random latency and schedules a delivery event in the **`EventScheduler`**.
5.  **Message Handling**: When the event fires, **`System::handleMessage`** routes it to the destination (another Cache, the Directory, or Memory).
6.  **Resolution & Logging**: Once the data is returned and the state is updated, a completion callback invokes **`System::logAccess`**, which records the resolver (e.g., "L2_0", "Memory") and the total latency to `trace.csv`.

## File Structure

### Core Logic (`include/` and `src/`)
- **`system.hpp/cpp`**: The orchestrator. It builds the cache hierarchy based on YAML config and manages the top-level simulation loop.
- **`cache.hpp/cpp`**: Defines the `Cache` class and `CacheLine` structure. It contains the logic for set-associativity, tag matching, and line allocation.
- **`cache_state.hpp/cpp`**: **The heart of the MSI protocol.** Uses the **State Pattern** where each MSI state is a class. Handles transitions, coherence messages (Data, Acks, Inval), and evictions.
- **`directory.hpp/cpp`**: Implements the centralized directory. Tracks sharers/owners for every block and coordinates coherence across the system.
- **`scheduler.hpp/cpp`**: A custom discrete-event engine using a priority queue to manage simulation time and event callbacks.
- **`message.hpp`**: Defines the `Message` types and the `Network` class that simulates communication latency.

### Policies & Wrappers
- **`replacement_policy.hpp/cpp`**: Polymorphic interface for cache line replacement. Includes `LRUPolicy`, `PLRUPolicy`, `LFUPolicy`, etc.
- **`write_policy.hpp/cpp`**: Strategy pattern for `WriteBack` vs `WriteThrough` behavior.
- **`wrapper.hpp`**: The `MemWrapper<T>` template. It uses an internal `Proxy` class to overload `operator=` and `operator T()` so that `*a = *b` automatically triggers the simulator.

### Infrastructure
- **`main.cpp`**: The trace-based simulator executable.
- **`configs/`**: YAML files defining system parameters (cache sizes, latencies, L2 grouping).
- **`tests/`**: Unit tests (`unit_tests.cpp`) and example memory traces.

---

## Data Structures

- **`CacheLine`**: Stores the block address, tag, a pointer to the current `MSIState` object, dirty bit, and a queue of pending acknowledgments.
- **`DirEntry`**: Tracks the `DirState` (I, S, M), the set of core IDs sharing the block, and the current owner.
- **`Event`**: A simple structure containing a timestamp, priority, and a `std::function` callback.

## Building and Running

### Prerequisites
- CMake 3.10+
- `libyaml-cpp-dev` (`sudo apt-get install libyaml-cpp-dev`)
- A C++17 compliant compiler

### Build
```bash
mkdir build && cd build
cmake ..
make
```

### Run Tests
```bash
./unit_tests
```

### Run Trace Simulation
```bash
./cache_sim ../configs/default.yaml ../tests/ls.trace
```
This will generate a `trace.csv` file in the current directory.

### Using the Wrapper in Code
```cpp
System sys(config);
int x = 0;
MemWrapper<int> wrapped_x(&x, 0, &sys); // Wrap 'x' for Core 0

*wrapped_x = 42; // Triggers detectMemAccess(0, WRITE, &x)
int val = *wrapped_x; // Triggers detectMemAccess(0, READ, &x)
```
